## Findings

### 1. P2 — A restored race checkpoint can crash the next game frame

Location: `src/simulation/saveValidation.ts:50-53, 103, 107`; consumption at `src/simulation/GameSimulation.ts:1702-1706` and `1725-1729`.

Reproduction: export `race-rough`, set `state.race.countdown = 0` and `runtimes[0][1].raceCheckpoint = raceCourse.length`, restore, call `update(1/60)`.

Observed: restore returns `true`, then `TypeError: Cannot read properties of undefined (reading 'x')`. The validator checks a nonnegative integer but never bounds it against this save's actual course. The same issue matters for AI checkpoints because they index the course too.

Required correction: validate checkpoint/course cross-record bounds and active-course requirements before hydration, with a defensive consumer guard. This is a blocker to a claim that accepted malformed saves cannot crash; it was not generated by ordinary play during this review.

### 2. P2 — `timeScale: 0` creates an accepted voyage with no gameplay exit

Location: `src/simulation/saveValidation.ts:100`; `src/simulation/GameSimulation.ts:666-669`.

Reproduction: export a newly started salvage encounter, change only `state.timeScale` to `0`, restore, hold throttle-up and call `update(1/60)` 600 times.

Observed: restore returns `true`; elapsed advances by zero; extraction returns `false`; return to harbor returns `false`. Pause/resume does not change `timeScale`. The normal UI has no speed-setting recovery control. Unlike an explicit pause, this remains frozen after resuming.

Required correction: accept only supported playable time scales, or normalize this field on restore. Very small positive values deserve the same practical consideration. This is a blocker to robust malformed-save recovery, not an ordinary exported-save failure.

### 3. P2 — Saved salvage duration is not checked against its objective

Location: `src/simulation/saveValidation.ts:64-73`; `src/simulation/GameSimulation.ts:531-532`.

Reproduction: export first-leg `lost-cargo` salvage, change only `voyage.encounter.target` from `12` to `1000000000`, restore.

Observed: restore returns `true` and uses that duration. The objective still says 12 seconds, but finishing now needs about 31.7 years of simulated time within the marker. Extraction is locked until completion; deliberately losing or clearing the save is the remaining escape.

Required correction: require authored target durations for salvage and escort, just as storm already requires exactly three gates. Tie active encounter identity/kind/terms to a legitimate route, with allowance for the previous completed encounter retained during the next route phase. This concerns an impossible playable state, not protecting a player from editing coin totals.

### 4. P2 — Completed battle records are not reconciled with target ship state

Location: `src/simulation/saveValidation.ts:66-68, 126-133`; `src/simulation/GameSimulation.ts:503-511, 527-528`.

Reproduction: export a fresh battle, set `encounter.completed = true`, `progress = target`, and `resolvedAt = elapsed`, leaving the enemy active and healthy.

Observed: restore returns `true`; the target remains active; `collectEncounterReward()` immediately returns `true`. If a frame runs first, encounter completion also disables AI decision updates, so the corruption is not corrected by simulation.

Required correction: for battle/boss encounters, reconcile progress/completion with the referenced targets' surrender/disabled state at the restore boundary. Keep normal aftermath valid. This is a semantic consistency gap; it does not itself crash or prevent finishing a voyage.

## Limits

Visual identity, crew animation quality, touch ergonomics, audio, and actual browser persistence/UI restoration were outside this simulation review. Full ordinary-input victory remains unproven here; the maintained completion tests use damage fixtures, which correctly test transitions but do not establish combat balance. A rudimentary combat pilot losing to the dangerous two-ship patrol is not classified as a bug. No security requirement for tamper-proof local saves is implied.
